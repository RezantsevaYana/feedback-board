# Подключить продукт к сервису

Для каждого нового продукта — 2 команды на сервере + 1 строка на сайте продукта. Деплой самого сервиса здесь не описан.

## Шаг 1. Зайти на сервер

Как именно — зависит от инфраструктуры (SSH / Forge Command runner / что-то ещё). Ниже команды написаны для Docker-варианта (как у нас в репе), но суть `artisan`-команд одна и та же в любом окружении.

```bash
ssh deploy@feedback.rocont.ru
cd /opt/feedback-board
```

## Шаг 2. Создать проект

```bash
docker compose exec backend php artisan project:create "Kerr Dental" \
    --slug=kerr \
    --origin=https://kerrdental.ru
```

Что делает:
- Создаёт запись в `projects`.
- Автоматически заводит стартовые категории («Баг», «Идея») и три системных статуса канбана (`Новое → Готово → Отклонено`). Админ потом сам донастроит.
- Печатает в консоль готовую строку `<script>` для вставки.

Что значат флаги:

| Флаг | Что это | Пример |
|---|---|---|
| `"Kerr Dental"` | Отображаемое имя проекта (видно на доске и в виджете). Можно по-русски. | `"Kerr Dental"`, `"Моё приложение"` |
| `--slug=kerr` | Короткий идентификатор, латиница + дефисы. Пойдёт в URL доски (`/kerr`) и в `data-project` виджета. Если не указать — сгенерится из имени. | `--slug=kerr`, `--slug=my-app` |
| `--origin=…` | Белый список сайтов, с которых разрешено слать посты в этот проект. Можно повторить несколько раз. Без него команда упадёт. См. раздел ниже. | `--origin=https://kerrdental.ru` |

## Шаг 3. Создать админа команды

```bash
docker compose exec backend php artisan admin:create maria@rocont.ru \
    --project=kerr \
    --name="Мария"
```

Что делает:
- Создаёт запись в `users` и прикрепляет её к указанным проектам.
- Генерит случайный безопасный пароль, **печатает его один раз в консоль** → скопировать и передать админу лично.
- Админ заходит на URL доски, жмёт «Вход для команды», логинится.

Что значат флаги:

| Флаг | Что это |
|---|---|
| `maria@rocont.ru` | Email, по которому админ будет логиниться. Уникальный на весь сервис. |
| `--project=kerr` | Slug проекта. Можно повторить (`--project=kerr --project=jlr`) → один человек админит оба проекта. |
| `--name="Мария"` | Отображаемое имя. Если не указать — возьмёт часть email до `@`. |

## Шаг 4. Отдать команде продукта строку виджета

```html
<script src="https://feedback.rocont.ru/widget.js" data-project="kerr" defer></script>
```

Разработчик продукта вставляет её **один раз** в основной layout (например, в `<head>` или перед `</body>`). Больше ничего не делает.

С этого момента:
- На сайте продукта справа внизу появляется кнопка «Обратная связь».
- Пользователь жмёт → форма → отправляет пост.
- Пост прилетает в проект на твоём сервисе.
- Админ видит его на `https://feedback.rocont.ru/<slug>` в режиме команды.

### Опциональные параметры скрипта

```html
<!-- кнопку виджета в левый нижний угол вместо правого -->
<script src="https://feedback.rocont.ru/widget.js"
        data-project="kerr"
        data-position="bottom-left"
        defer></script>
```

Пока поддерживается только `data-position` (`bottom-right` — дефолт, или `bottom-left`).

## Шаг 5. Что передать команде продукта

- URL доски: `https://feedback.rocont.ru/<slug>`
- Email и пароль админа (из вывода `admin:create` или `admin:password`).
- Строку `<script …>` для вставки на сайт.

## Про `--origin` — зачем он

Это белый список сайтов, которым разрешено слать посты в этот проект. Защищает от того, чтобы кто-то не скопировал `<script data-project="kerr">` на свой сайт и не флудил на чужую доску.

Проверка — через заголовок `Origin`, который браузер проставляет в cross-origin запросы автоматически. Подделать его из JavaScript нельзя. Если `Origin` не совпадает с `allowed_origins` проекта — бэкенд возвращает 403.

Формат:
- `https://kerrdental.ru` — конкретный боевой домен.
- `https://stage.kerrdental.ru` — stage. Можно добавить вторым `--origin`.
- `http://localhost:*` — любой локальный порт (для разработчика продукта на его машине).
- **Нельзя:** `https://*.ru` — wildcard по домену запрещён, только по порту.

Указать хотя бы один — иначе `project:create` упадёт с ошибкой `«Укажите хотя бы один --origin»`.

## Добавить ещё один origin позже

Отдельной `artisan`-команды пока нет, проще SQL:

```sql
UPDATE projects
SET allowed_origins = allowed_origins || '["https://new-stage.kerrdental.ru"]'::jsonb
WHERE slug = 'kerr';
```

Или через tinker:
```bash
docker compose exec backend php artisan tinker --execute="
  \$p = \App\Models\Project::where('slug', 'kerr')->first();
  \$p->allowed_origins = array_merge(\$p->allowed_origins, ['https://new-stage.kerrdental.ru']);
  \$p->save();
"
```

## Если админ забыл пароль

```bash
docker compose exec backend php artisan admin:password maria@rocont.ru
```

Генерит новый случайный пароль, печатает его один раз, **завершает все старые сессии** (придётся залогиниться заново).

## Чеклист подключения нового продукта

- [ ] `project:create "<Имя>" --slug=<slug> --origin=https://<боевой-домен>`
- [ ] `admin:create <email> --project=<slug>` → забрать пароль из вывода
- [ ] Отдать разработчику продукта: `<script src="…/widget.js" data-project="<slug>" defer>`
- [ ] Отдать админу: URL `https://feedback.rocont.ru/<slug>`, email, пароль
- [ ] Админ логинится и настраивает категории/столбцы под свой продукт

Переделывать и пересобирать сервис при добавлении проекта **не нужно** — всё работает мгновенно после `project:create`.
