# Роли и закрытые доски — продуктовый план

Сейчас у доски есть владелец (`owner_id`) и команда без ролей (pivot `project_user`), а сама доска всегда открытая: читать, предлагать и голосовать может любой без входа. Этого не хватает двум сценариям студии: внутренние продукты компании (доска только для своих) и клиентские проекты (клиент в команде доски студии).

Документ рассчитан на продолжение в разных сессиях. Внизу чеклист, отмечай пройденное.

Прототип экранов (холст): https://claude.ai/artifact/P78E3Khqf9SQ4fUHRu17qK (по умолчанию открыт только владельцу; коллегам — через «Поделиться»).

## 1. Продуктовые решения (не пересматриваем)

- **Две независимые настройки** вместо «типов досок»: *кто видит доску* и *кто что может внутри*. Все сценарии — их сочетания.
- **Видимость:** `public` (как сейчас) и `private` (только участники, со входом). Режим «по ссылке» — не делаем, пока не попросят.
- **Доступ по домену почты** для закрытой доски: `@rocont.ru` → любой с **подтверждённой** почтой на домене получает роль «Участник» без приглашения.
- **Роли (минимум, осознанно):**

  | | Читать | Предлагать и голосовать | Разбор: статусы, ответы, скрытие | Настройки и участники | Удалить доску |
  |---|---|---|---|---|---|
  | Владелец (`owner_id`, один) | ✓ | ✓ | ✓ | ✓ | ✓ |
  | Администратор | ✓ | ✓ | ✓ | ✓ | — |
  | Команда | ✓ | ✓ | ✓ | — | — |
  | Участник | ✓ | ✓ | — | — | — |
  | Гость (без аккаунта) | только открытая | только открытая | — | — | — |

  Отдельных ролей «наблюдатель» и «клиент» нет: клиент — это «Участник», «Команда» или «Администратор» по задаче.
- **Участники закрытой доски могут предлагать идеи и голосовать.**
- **Голоса на закрытой доске привязаны к аккаунту** (один человек — один голос). **Кто голосовал, видит только команда доски** (владелец, админ, команда); участники видят только число. На открытых досках голоса анонимные, как сейчас.
- **Клиентские доски принадлежат студии** (вариант А). Передачу владения клиенту не делаем. Следствие: на каждую клиентскую доску ставить хотя бы одного администратора от студии, пока нет пространств.
- **Приглашение:** письмо в стиле сервиса, ссылка живёт 7 дней, можно отправить ещё раз или отменить. Новый человек регистрируется по ссылке, почта считается подтверждённой.
- **Смена видимости открытая → закрытая:** старые анонимные голоса остаются в счётчике без имён; в настройках предупреждаем.
- **Вход в закрытую доску — по почте, без пароля** (ряд 3 на холсте). Человек вводит рабочую почту и получает письмо с кнопкой и 6-значным кодом. Ссылка и код живут 15 минут и срабатывают один раз. Открытие письма = подтверждение почты, отдельного шага нет. Аккаунт создаётся сам. При первом входе спрашиваем только имя (подставляем из почты). Сессия около 30 дней.
  - Ответ формы всегда одинаковый («Проверьте почту»): по форме нельзя узнать, кто есть в доске. Без доступа приходит письмо «У этой почты нет доступа».
  - Код нужен для случая «почта на телефоне, доска на компьютере».
  - Владельцы и команда по-прежнему входят в кабинет с паролем. Делать ли вход по ссылке для всех — отдельное решение.

## 2. Сценарии

1. **Внутренний продукт компании.** Закрытая доска, домен `@компания.ru`. Сотрудники — участники, разработчики продукта — команда.
2. **Внешний сервис.** Открытая доска (текущее поведение). Свои — команда, пользователи — гости.
3. **Клиентский проект студии.** Владелец — студия, её разработчики — команда, представитель клиента — участник / команда / админ. Пользователи клиентского продукта — гости открытой доски.

## 3. Этапы

### Этап 1. Роли и участники (доски остаются открытыми)
- [ ] БД: `project_user.role` (`admin` | `team` | `member`); миграция: существующие записи → `team`. Владелец остаётся в `owner_id`, не дублируем.
- [ ] БД: таблица приглашений (email, role, token, expires_at, invited_by, accepted_at).
- [ ] Права: вместо одного `managesProject` — `canTriage` (владелец, админ, команда), `canConfigure` (владелец, админ), `canDelete` (владелец). Пройти ~20 мест, где сейчас `managesProject` / `authorizeOwner`.
- [ ] API: список участников, приглашение, смена роли, удаление, отмена и повтор приглашения, принятие приглашения.
- [ ] Письмо «Вас пригласили в доску …» (`views/mail/`, общий шаблон из `views/vendor/mail`).
- [ ] Страница `/app/invite/{token}`: регистрация (почта подставлена и подтверждена) или вход.
- [ ] Настройки → раздел «Участники».
- [ ] Хаб: блок «Вас пригласили» с меткой роли; кнопки по ролям (у команды нет «Настройки»).
- [ ] Тесты: права каждой роли, приглашения (принять / истекло / отменено), миграция.

### Этап 2. Закрытые доски
- [ ] БД: `projects.visibility`, `projects.allowed_email_domains`.
- [ ] БД: `votes.user_id`, `posts.author_user_id` (nullable) — голос и автор по аккаунту на закрытой доске.
- [ ] Доступ: расширить `EnsureProjectPublished` — закрытая доска пускает участников любой роли и подтверждённую почту на разрешённом домене.
- [ ] Экраны «Это закрытая доска, войдите» и «У вас нет доступа».
- [ ] На закрытой доске голосовать и предлагать только после входа; автор из аккаунта, без поля «Ваше имя».
- [ ] Команде — список голосовавших по нажатию на счётчик.
- [ ] Настройки → «Доступ»: Открытая / Закрытая + домены, предупреждение про старые голоса.
- [ ] Виджет на закрытой доске просит войти.
- [ ] Вход по почте: таблица одноразовых входов (email, hash ссылки, hash кода, project_id, expires_at 15 мин, used_at), попытки ввода кода ограничены (5 на код), повторная отправка не чаще раза в минуту.
- [ ] API: «прислать ссылку» (ответ всегда одинаковый), вход по ссылке, вход по коду. Вход создаёт аккаунт, если его нет, и сразу отмечает почту подтверждённой.
- [ ] Письма: «Вход в доску» (кнопка + код) и «У этой почты нет доступа».
- [ ] Экраны: «Войти в доску» (одно поле), «Проверьте почту» с полем для кода (шестая цифра — сразу вход), «Как вас подписывать?» при первом входе.
- [ ] Экран 2.2: «Войти» ведёт на вход по почте; ссылка «Войти с паролем» для владельцев и команды.

### Этап 3. Пространства (когда клиентских досок станет много)
Участники пространства получают роль на всех его досках сразу. Модель не закрывать: роль на связке «человек — доска», потом добавится «человек — пространство».

### Этап 4. Вход в виджет без отдельного логина
Сервер продукта подписывает email пользователя секретом доски, виджет узнаёт человека (как SSO-токен у Canny / Featurebase). Нужно для закрытых досок во внутренних продуктах.
